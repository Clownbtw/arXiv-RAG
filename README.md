# 📚 arXiv RAG: вопросы к научным статьям на русском и английском

RAG-система поиска по аннотациям статей arXiv (около 22,5 тыс. статей с тегами `cs.CL` / `cs.LG`).
Принимает вопрос на русском или английском, находит релевантные статьи, отвечает **только по ним**
и показывает источники. Интерфейсы: Streamlit-приложение и Telegram-бот.

> Учебный прототип, а не промышленный сервис (см. [ограничения](#ограничения)).

## Как это работает

```
вопрос (RU/EN)
   │  перевод на английский (LLM; английский вопрос не трогаем)
   ▼
E5-эмбеддинг запроса ──► Chroma (cosine), top-20 кандидатов
                                  │
                                  ▼
                  cross-encoder reranking → top-5
                                  │
                                  ▼
          LLM отвечает только по найденным аннотациям,
          ссылаясь на них номерами [1], [2]...
                                  │
                                  ▼
        ответ + источники (список собирает код, не LLM)
```

| Этап | Инструмент |
|---|---|
| Очистка данных | pandas (фильтр по категориям, дубли, LaTeX-разметка) |
| Эмбеддинги | `intfloat/multilingual-e5-base` (768 dim, префиксы `query:` / `passage:`) |
| Векторная БД | ChromaDB, метрика cosine |
| Reranking | `cross-encoder/ms-marco-MiniLM-L-6-v2` |
| LLM | любой OpenAI-совместимый API (Ollama, Groq, OpenRouter, DeepSeek и др.) |
| Интерфейсы | Streamlit, aiogram (Telegram) |

Ключевые решения:
- **Источники формирует код, а не LLM**: название и категории берутся из базы, поэтому модель не может выдумать название статьи.
- **LLM подключается через переменные окружения**: смена провайдера не требует правок кода.
- **Перевод вопроса перед поиском**: абстракты английские, а русские запросы напрямую дают заметно более низкую близость (см. ниже).

## Метрики

### 1. Ручная оценка поиска (до reranking): 14 запросов × топ-5

Запросы разных типов: прямые, перефразированные, русскоязычные, вне домена. Каждый результат оценён вручную:
2 = статья по теме, 1 = рядом, 0 = не по теме. Использовался только векторный поиск E5.

| Показатель | Значение |
|---|---|
| Запросов по теме с релевантной статьёй в топ-3 | **12 из 13** (92%) |
| Средняя доля релевантных статей в топ-5 | **0,45** |
| Запросы с долей ≥ 0,6 | 7 из 13 |
| Слабые запросы (доля ≤ 0,2) | 4 из 13: federated learning, self-supervised, few labels, сжатие сетей |

Запрос вне домена («рецепт шоколадного торта») в метрики не входит.

### 2. Что показала оценка

- **Слабые темы не объясняются нехваткой данных.** По грубому подсчёту регулярными выражениями в базе около 200 статей по federated learning, около 750 по self-supervised и более 1000 по сжатию сетей, а доля релевантных в топ-5 всего 0,0–0,2. Узкое место в качестве первичного поиска, поэтому добавлен reranking.
- **Порог по cosine score практически бесполезен.** Средняя близость для статей с оценкой 0 / 1 / 2: 0,851 / 0,874 / 0,875. У E5 значения сжаты в диапазоне 0,80–0,90, и по ним нельзя отделить хорошие результаты от плохих. Защита от ответов «не по теме» сделана инструкцией в промпте и опциональным порогом по оценке reranker (`MIN_RERANK`).
- **Русский запрос напрямую даёт более низкую близость** к английским абстрактам: максимум 0,80 у «обучения с подкреплением» против 0,86–0,90 у английских запросов. Отсюда перевод вопроса перед поиском.

## Плюсы и минусы

**Плюсы**
- Полный сквозной цикл: данные → индекс → поиск → reranking → ответ с источниками → два интерфейса.
- Качество измерено, а не заявлено: ручная оценка и скрипт с метриками, по которым можно сравнивать модели «было → стало».
- Кросс-язычность: русский вопрос к англоязычному корпусу.
- Ответы проверяемы: каждое утверждение привязано к номеру статьи, список источников собирает код.
- Лёгкая инфраструктура: индекс небольшой (векторы в float16), реранкер маленький, LLM заменяема, в том числе на локальную.
- Есть защита от перегрузки бота: лимит частоты, длины вопроса и параллельных запросов.

**Минусы**
- Только аннотации: нет деталей из полных текстов (методы, цифры, таблицы).
- Статичный снимок датасета: новые статьи не добавляются.
- Качество ответа зависит от LLM; малые локальные модели хуже пишут по-русски.
- Перевод вопроса добавляет задержку и зависимость от LLM; ошибка перевода портит поиск.
- Автоматической оценки ответов нет: проверяется поиск, а не отсутствие галлюцинаций в тексте ответа.
- Индекс Chroma строится в памяти при каждом запуске (минуты); для продакшена нужен постоянный.
- Оценка на небольшой выборке и без доверительных интервалов.

## Сферы применения

Прототип показывает общий шаблон «вопрос на естественном языке → ответ с источниками по закрытому корпусу». Корпус заменяется без изменений в архитектуре.

- **Литературный обзор и онбординг в тему.** Быстро понять, что делают в области, и получить список статей для чтения.
- **Научные группы и лаборатории.** Внутренняя база статей и отчётов с вопросами на русском.
- **Технологический скаутинг и патентный поиск.** Поиск по коротким техническим описаниям (статьи, патенты, аннотации проектов).
- **Корпоративная база знаний.** Тот же шаблон для регламентов, тикетов поддержки, FAQ при замене корпуса.
- **Обучение.** Подбор материалов к теме курса или дипломной работы.

Для реального использования нужны полные тексты, актуализация корпуса и оценка качества на реальных запросах пользователей.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # укажите LLM-провайдера и токен бота

# 1. Данные: очистка arxiv_data.csv и эмбеддинги -> data/
python prepare_data.py --raw arxiv_data.csv        # --limit 2000 для быстрой проверки

# 2. Интерфейсы
streamlit run app.py            # веб-приложение
python bot.py                   # Telegram-бот (нужен TELEGRAM_BOT_TOKEN)

# 3. Метрики на тестовом наборе
python evaluate.py eval/eval_set.json
```

LLM: по умолчанию локальная Ollama (`ollama pull qwen2.5:7b`). Для облачного провайдера задайте
`LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` в `.env` (актуальные имена моделей смотрите у провайдера).
Расчёт эмбеддингов лучше делать на GPU (например, в Google Colab) и положить готовые файлы в `data/`.

## Ограничения

- Ответ строится по аннотациям, а не по полным текстам.
- Источники ведут на поиск по названию на arXiv, а не на конкретный идентификатор статьи: в исходных данных идентификаторов нет.
- Исходный датасет в репозиторий не включён; перед публикацией данных проверьте его лицензию.
- Результаты ручной оценки получены на небольшой выборке и могут отличаться на другом корпусе или другой LLM.

## Что можно улучшить

Сравнить E5 с английскими моделями эмбеддингов (например, BGE) на том же тестовом наборе; перейти на постоянный индекс;
добавить автоматическую оценку обоснованности ответов; хранить идентификаторы arXiv; разбивать полные тексты на фрагменты.
